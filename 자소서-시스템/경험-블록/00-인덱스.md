# 경험 블록 인덱스

블록 원본(`경험-블록-통합.md`)을 매번 다 읽으면 느리다. JD 매칭할 때는
이 1줄 인덱스만 먼저 스캔해서 후보 3~4개만 고른 뒤 원본을 연다.
(출처: 구독편 #2-A — 인덱스 분리가 자소서 작성 속도를 5~10배 올림)

## 블록 인덱스

| 블록 | 출처 | 핵심 키워드 | 핵심 성과 |
|---|---|---|---|
| A | 화장품 제조업체 QC (부자재검사) | 이상탐지, 사전예방, 데이터기반판단 | 펌프용기 불량 20% 확인 → 출고 전 사용중단 |
| B | 화장품 제조업체 QC (교육이수) | 미생물시험, 원료검사, 샘플링 | 검사범위 부자재→원료 확장 (수치 보강 필요) |
| C | 화장품 제조업체 생산현장 (협업) | 커뮤니케이션, 이해관계자관리 | 요청형 소통 전환 → 협업 개선 (수치 보강 필요) |

전체 원본은 `경험-블록-통합.md` 참고. 블록이 쌓이면 이 표에 한 줄씩 추가한다.

## JD 역량 → 블록 매칭표

공고 하나 볼 때마다 "이 공고는 A, C 조합이면 되겠다"를 5초 안에 판단하기 위한 표.

| JD 역량 | 매칭 블록 |
|---|---|
| 이화학시험 / 원료·자재 검사 | A, B |
| 미생물시험 | B |
| 품질 시스템 / 사전예방적 품질관리 | A |
| 현장 커뮤니케이션 / 협업 | C |

## 블록 만드는 법 — 두 가지 루트

**루트 1: 대화 방식** (파일로 정리된 자료가 별로 없을 때, 알바/동아리/사이드 경험)
1. 경험 하나를 편하게 말로 풀어서 씀 (완벽한 문장 아니어도 됨)
2. `experience-block-builder` 스킬에 붙여넣고 블록화 요청
3. Claude가 뽑아낸 S/A/R 초안에서 과장된 수치, 잘못 매칭된 직무만 고침
4. 반복 (하루 2~3개씩 해도 일주일이면 15~20개)

**루트 2: 폴더 일괄 투입** (이력서/경력기술서/포트폴리오가 이미 있는 경력자)
1. 이력서/경력기술서/포트폴리오/수상내역/자격증을 한 폴더에 모음
2. `experience-block-builder` 스킬에 그 폴더 경로를 주고 "전부 읽고 블록화해줘" 요청
3. 결과를 회사/프로젝트별로 읽으며 과장된 수치, 빠진 맥락, 잘못 매칭된 직무 세 가지만 교정

두 루트 섞어 써도 됨 — 경력 블록은 일괄 투입, 사이드 프로젝트 블록은 대화 방식.

## 블록 표준 포맷

```markdown
## 블록 [ID]: [경험 한 줄 제목]
- 출처: [회사/프로젝트/활동명]
- 상황(S): [배경, 왜 문제였는지]
- 행동(A): [무엇을 했는지 + 판단 근거(왜 그 방법을 택했는지)]
- 결과(R): [수치로 된 결과]
- 태그: [직무/역량 키워드, 매칭용]
```

경험이 대단할 필요 없음 — "문제를 인식했고 → 뭔가 바꿨고 → 결과가 나왔다" 3박자면
알바/동아리/자취 생활비 절약 경험도 블록이 됨. 수치는 체감이어도 된다.
