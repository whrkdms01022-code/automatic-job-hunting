# 채용 자동화 시스템

공고 발견 → 경험 블록 → 자소서 생성 → 자소서 채점 → 제출 관리 → 링크드인 →
면접 코치 → 면접 지식베이스, 여러 단계가 입력/출력으로 물려 있는 개인 채용 파이프라인.

핵심 원칙: **매번 처음부터 다시 굴리지 않는다.** 어제 거른 기준, 어제 채점한 기준,
어제 준비한 면접 답변을 오늘 또 새로 만들지 않도록, 판단 기준과 결과물을 전부 파일로 고정한다.

참고: [@moneynena](https://x.com/moneynena) 취준 자동화 시리즈 (공개편 + 구독편 전체 확인 후 반영)

## 폴더 구조

```
채용-트래커/            공고 필터 통과 결과 + 지원 상태 (우선순위/진입난이도 태그 포함)
자소서-시스템/
  ├─ 경험-블록/          STAR 구조 경험 블록 + 인덱스 + JD매칭표
  ├─ 채점기준표.md        100점 배점(감점/가점) + 글쓰기 원칙 + 구조전략 + AI냄새 체크리스트
  └─ 개인체크리스트.md    88점 달성 후 마지막 확인용
링크드인-시스템/         프로필 세팅 가이드/프롬프트
면접-코치/               채점기준(4단 25점, 70점컷) + 이력검증 + 복기 절차
면접-지식베이스/          누적되는 카드 (경험/기술/설계 케이스, 30초/2분/10분 3단 깊이)
.claude/skills/          각 단계를 실행하는 스킬
```

## 흐름

```
[공고 알림/URL/목록 붙여넣기]
    ↓ job-filter (직무/지역/제외키워드 필터 + 진입난이도 태그 → 트래커 기록)
[채용-트래커/트래커.md]
    ↓ (지원할 회사 결정)
experience-block-builder (아직 경험 블록이 없다면 먼저 — 대화 또는 폴더 일괄 투입)
    ↓
coverletter-writer (JD+블록 매칭 → 초안 생성. 채점은 절대 스스로 안 함)
    ↓ (반드시 새 세션에서)
coverletter-grader (100점 기준 채점, 88점 넘을 때까지 최대 5회 루프)
    ↓ 88점 달성
submit-tracker ("OO사 제출했어" 한마디 → 트래커+자소서 상태 동시 갱신)
    ↓ (병렬)
linkedin-optimizer (프로필 프롬프트 1회 실행)
    ↓
[서류 통과 → 면접 확정]
    ↓
interview-coach (이력검증 → 예상질문 20개 → 4단 액션 답변채점 → 압박질문 → 복기)
    ↓ 면접 후
interview-kb (새로 나온 질문/모범답변을 카드로 추가, JD 보고 관련 카드 검색)
    ↓
[면접-지식베이스 카드 누적 → 다음 회사 준비 30분]
```

## 설계 시 반영한 핵심 원칙 (구독편에서 확인한 내용)

- **생성과 채점은 반드시 분리, 채점은 매번 새 세션**: 한 대화에서 "써줘+고쳐줘"를 같이 시키면
  AI가 자기 글을 방어해서 감점을 제대로 못 매긴다. `coverletter-writer`와 `coverletter-grader`를
  다른 스킬로 쪼갠 이유.
- **공고 지역은 메일 제목이 아니라 URL을 열어서 재확인**: 제목에 지역이 안 나오는 경우가 많아서
  이 확인이 없으면 엉뚱한 지역 공고에 자소서까지 쓰게 된다.
- **면접 질문은 일반론이 아니라 자소서 문장에서 파생**: "역량 × 경험 교차"로 만들어야 적중률이
  올라간다. 예상질문 만들기 전에 이력 검증(과장/모순 리스크)부터 먼저 하는 게 순서.
- **후처리(제출/포기)는 한마디로**: 자소서 쓰는 것보다 "쓴 다음 트래커/파일 정리"가 건수가
  쌓이면 더 오래 걸린다. `submit-tracker`가 이걸 담당.

## 현재 상태

- 전 단계 스킬 골격 완성. QA/QC 직무 기본값으로 채워져 있어 다른 직무면 `채점기준표.md`의
  "직무 연관성" 예시와 `트래커.md`의 필터/우선순위만 실제 값으로 교체하면 됨.
- 경험 블록, 자소서, 면접 지식베이스는 전부 예시 데이터 — 실제 이력/경험을 넣어야 작동함.
- Gmail 자동 파싱, 캘린더 연동, 텔레그램(OpenClaw) 원격 봇은 이 세션에 해당 연동 도구가 없어서
  구현하지 않음. 필요하면 MCP 연동을 붙이는 것부터 시작 — 스킬들은 연동이 생겨도 구조를
  바꿀 필요 없이 그대로 확장 가능하게 짜둠.

## 다음에 할 일 (한 번에 다 만들지 않기)

1. `자소서-시스템/채점기준표.md`의 직무 연관성 예시를 실제 지원 직무로 확정
2. `experience-block-builder`로 실제 경험 5개 이상 블록화 (대화 방식 또는 폴더 일괄 투입)
3. 실제 JD 1건으로 `coverletter-writer` → (새 세션) `coverletter-grader` 흐름 검증
4. 관심 공고 몇 건으로 `job-filter` 필터 기준 튜닝
5. 면접이 잡히면 `interview-coach` → `interview-kb` 순서로 실전 데이터 채우기
