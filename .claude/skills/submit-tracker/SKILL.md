# 제출/포기 처리 — 한마디로 트래커 정리

목표: 자소서를 쓴 다음의 "후처리"(트래커 상태 변경, 자소서 파일 상태 변경)를
사용자의 짧은 한마디로 한 번에 끝낸다. 후처리를 매번 수동으로 하면 3곳(자소서 파일/
트래커/캘린더)을 다 고쳐야 해서, 지원 건수가 쌓일수록 이게 자소서 쓰는 시간보다 커진다.

## 인식할 말투 (사용자 말투 그대로 받는다 — 풀어서 다시 말하게 하지 않는다)

- "A사 제출했어" / "A사 냈어" → A사 제출완료 처리
- "A사 포기" / "A사 버려" → A사 포기 처리
- "A사, B사, C사 포기" → 여러 건 한 번에 포기 처리
- "A사 ㄱㄱ" → A사 자소서 작업을 계속 진행 (상태를 "작성중"으로, 또는 다음 단계 스킬 안내)
- "이미 냈을텐데" → 트래커에서 A사 상태를 다시 확인해서 알려준다
- "뭘 물어, 그냥 해" → 애매한 부분 있어도 질문하지 말고 가장 합리적인 처리로 바로 진행

## 절차 — 제출 처리

1. 메시지에서 회사명을 추출한다. 트래커에서 해당 회사명(또는 유사한 이름)을 찾는다.
   여러 개 매칭되면 어느 건인지 물어본다.
2. `채용-트래커/트래커.md`에서 해당 행의 상태를 `제출완료`로 바꾸고 오늘 날짜를 기록한다.
3. 연결된 자소서 파일이 있으면 그 파일의 상태도 `done`으로 표시한다 (파일 상단에 상태 메타가
   없으면 새로 추가한다).
4. (캘린더 연동이 있는 경우만) 해당 회사 마감 이벤트를 완료 표시로 바꾼다. 캘린더 연동이 없으면
   이 단계는 건너뛴다 — 실패로 취급하지 않는다.
5. "OO사 제출완료 처리 완료" 한 줄 확인 메시지로 끝낸다. 장황한 요약 붙이지 않는다.

## 절차 — 포기 처리

1. 메시지에서 회사명(들)을 추출한다. 복수면 한 번에 전부 처리한다.
2. 트래커에서 해당 행(들)의 상태를 `포기`로 바꾼다.
3. (캘린더 연동이 있는 경우만) 해당 마감 이벤트를 삭제하거나 취소 표시한다.
4. "N건 포기 처리 완료" 로 끝낸다.

## 현황 요약 요청 시

"지금 상황 어때" 같은 질문에는 트래커를 스캔해서
`지원완료 N | 작성중 N | 미지원 N | 포기 N` 형태로 짧게 답한다.

## 주의

- 회사명이 트래커에 없으면 지어내서 처리하지 말고, "트래커에 그 회사가 없는데 새로 추가할까요?"라고 확인한다.
- 트래커와 자소서 파일 상태가 이미 어긋나 있으면 ("이미 냈을텐데" 같은 경우) 임의로 덮어쓰지 말고 실제 상태를 물어서 정합성을 맞춘다.
