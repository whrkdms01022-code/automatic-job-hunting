# 경험 블록 빌더

목표: 사용자의 경험을 S(상황)/A(행동+판단근거)/R(결과+수치)/태그 구조로 뽑아내
`자소서-시스템/경험-블록/00-인덱스.md`와 `경험-블록-통합.md`에 등록한다.

## 두 가지 모드 — 입력 형태로 자동 판단

**모드 1: 대화 방식** — 사용자가 경험을 말로 풀어서 준 경우
1. 편하게 쓴 문장이어도 그대로 받는다 (완벽한 문장 요구하지 않는다).
2. `00-인덱스.md`의 표준 포맷에 맞춰 S/A/R/태그로 구조화한다.
3. 결과를 보여주고 "과장된 부분/빠진 맥락/이상한 매칭"이 있는지 사용자에게 확인시킨다.
4. 확정되면 블록 ID를 부여하고 인덱스 표 + 통합 파일에 추가한다.

**모드 2: 폴더 일괄 투입** — 사용자가 이력서/경력기술서/포트폴리오 폴더 경로를 준 경우
1. 폴더 안 파일(PDF/docx/md)을 전부 읽는다.
2. 회사/프로젝트별로 내용을 병합하고 STAR 구조로 블록화한다.
3. 수치 성과는 원본에 있는 것을 우선 사용하고, 없으면 지어내지 말고 "보강 필요"로 표시한다.
4. 한 번에 여러 블록이 나오므로, 사용자에게 "과장된 수치 / 빠진 맥락 / 잘못 매칭된 직무" 세 가지만
   검토해달라고 요청한다.

## 안전장치 (반드시 지킬 것)

- 없는 경험을 지어내지 않는다. 수치가 불확실하면 "보강 필요"로 표시하고 사용자에게 물어본다.
- 톤: 단문(~했음 체), 능동 동사 우선, AI 냄새(과도한 존댓말/클리셰) 금지.

## 인덱스/매칭표 갱신

블록을 추가할 때마다:
1. `00-인덱스.md`의 "블록 인덱스" 표에 블록ID/출처/핵심키워드/핵심성과 한 줄 추가
2. 사용자가 JD를 주면 "JD 역량 → 블록 매칭표"에도 매칭 결과를 추가

## 출력

블록 5개 미만이면 자소서 작성을 시작하기엔 이르다고 안내하고 계속 추가를 권한다.
10개 이상 쌓이면 이력서 프로젝트 섹션에도 그대로 쓸 수 있다고 안내한다.
