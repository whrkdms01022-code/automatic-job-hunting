# 공고 필터 + 트래커 입력 (붙여넣기 모드 / 능동 검색 모드)

목표: 공고를 `채용-트래커/트래커.md`의 필터 기준(직무/지역/경력/제외 키워드)으로 걸러서,
통과한 공고만 진입난이도 태그와 함께 트래커 표에 새 행으로 추가한다. 이미 검토한 공고는
`채용-트래커/검토완료-로그.md`를 확인해 다시 추천하지 않는다.

## 두 가지 모드

**모드 1: 붙여넣기** — 사용자가 공고 알림 메일 본문, URL, 목록을 직접 준 경우 (아래 "붙여넣기 절차")

**모드 2: 능동 검색** — 사용자가 "오늘 공고 추천해줘" / "브리핑" 이라고 하거나, 매일 자동
실행되는 스케줄러가 이 스킬을 호출한 경우. 이메일 연동이 없으므로, 사람인/잡코리아의
공개 검색 결과를 WebSearch/WebFetch로 직접 조회한다 (로그인 기반 "맞춤 추천"이 아니라
조건 검색 결과라서 개인화 추천보다는 커버리지가 다소 낮을 수 있다는 걸 감안).

## 공통 절차

1. `채용-트래커/트래커.md`를 읽어 필터 기준, 우선순위, 제외 키워드를 확인한다.
2. `채용-트래커/검토완료-로그.md`를 읽어 이미 검토된 공고(회사명+직무명 기준, 통과/탈락
   무관)를 파악한다.
3. 공고 후보를 모은다 (모드별로 아래 참고).
4. 검토완료 로그에 이미 있는 공고는 완전히 스킵한다 — 언급조차 하지 않는다.
5. 남은 신규 공고에 대해 필터링한다:
   - 직무명이 트래커 기준과 일치/유사한가
   - 지역이 기준 지역에 포함되는가 — 메일/검색결과 타이틀만으로 판단하지 않는다.
     공고 URL을 WebFetch로 열어서 지역을 재확인한 뒤에만 통과시킨다.
   - 경력 조건이 맞는가
   - 제외 키워드(코딩테스트 필수/교대근무/인턴 등)가 공고 내용에 있는가 — 있으면 탈락
6. 통과한 공고에 우선순위(⭐/🔵)와 진입난이도 태그([진입↑]/[진입→]/[진입↓])를 매긴다.
   판단이 애매하면 태그 없이 둔다.
7. 통과한 공고는 트래커 표에 `상태: 신규`로 새 행 추가. 탈락한 공고는 트래커에 넣지 않는다.
8. **검토한 공고는 통과/탈락 관계없이 전부 `검토완료-로그.md`에 오늘 날짜로 기록한다** —
   이게 없으면 내일 같은 공고가 다시 후보로 뜬다.
9. 요약을 준다: "신규 검색 N건 중 M건 통과, K건은 이미 검토했던 공고라 스킵".

## 모드 1: 붙여넣기 절차 (공통 절차 3번에서)

입력에서 회사명, 직무명, 마감일, 공고 링크(또는 식별자)를 추출한다. 여러 플랫폼에서
같은 공고가 중복으로 들어올 수 있다 — 회사명+직무명이 같으면 플랫폼이 달라도 중복 처리.

## 모드 2: 능동 검색 절차 (공통 절차 3번에서)

트래커의 필터 기준(직무/산업/지역/경력)으로 사람인·잡코리아의 공개 검색 URL을 구성해
WebSearch 또는 WebFetch로 오늘 기준 신규 공고를 조회한다. 검색 결과에서 회사명/직무명/
마감일/링크를 추출한다. 자소설닷컴 등 추가 소스가 있으면 같이 조회해도 좋다.

이 모드에서 사용자가 특정 공고에 "지원할래"/"ㄱㄱ"라고 답하면, 바로
`experience-block-builder`(경험 블록이 부족하면) 또는 `coverletter-writer`로 이어서
자소서 작성까지 그 자리에서 진행한다.

## 주의

- 애매한 경우(직무명이 비슷하지만 확신이 안 서는 경우)는 임의로 걸러내지 말고 사용자에게 물어본다.
- 이미 트래커에 있는 회사+직무 조합은 중복 추가하지 않는다.
- 검토완료 로그 기록을 빠뜨리면 중복 추천 방지가 깨지므로, 8번 단계는 절대 생략하지 않는다.
